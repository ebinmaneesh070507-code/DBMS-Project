# EcoMind Backend — Campus Incident Response System

Express + MongoDB API. A user photographs a messy/full area on campus, picks
a zone, and Gemini triages the photo — waste types, severity, whether a
response team should be dispatched, and what they should bring. Response
teams claim incidents off a live board and resolve them. Everything is real
data; nothing in this app is hardcoded or simulated at the schema level.

## Roles

- **citizen** — reports incidents, sees their own contributions + live analytics
- **responder** — claims open incidents off the live board, resolves them
- **admin** — sees everything across every zone, can also claim/act as a
  responder (simulation mode). Granted automatically to any email listed in
  `ADMIN_EMAILS` the moment they sign in with Google.

New users pick Citizen or Responder themselves on first login (or switch
anytime from the frontend's profile menu) via `PATCH /api/auth/role`.

## 1. Install & configure

```bash
cd ecomind-backend
npm install
cp .env.example .env
```

Fill in `.env`:
- `MONGO_URI` — your MongoDB connection string
- `GEMINI_API_KEY` — free key from https://aistudio.google.com/app/apikey
- `GOOGLE_CLIENT_ID` — **OAuth Client ID** (not a Maps/Generative AI key) —
  see the Google Sign-In setup section below
- `ADMIN_EMAILS` — comma-separated list; the email(s) here get admin access
  automatically on their first Google sign-in
- `JWT_SECRET` — any long random string

## 2. Seed your campus zones

Open `src/utils/seed.js` and edit the `ZONE_NAMES` array to your real block
names (it currently has placeholders: Psychology Block, Hostel Block, Centre
of Excellence, Main Academic Block, Central Library, Sports Complex). Then:

```bash
npm run seed
```

You can also add/rename/delete zones later from the admin UI without
touching this file again.

Nothing else is seeded — no fake incidents, no fake responders. All of that
is real data generated by actually using the app.

## 3. Run

```bash
npm run dev
```

Health check: `GET http://localhost:5000/api/health`

## 4. Google Sign-In setup

This needs an **OAuth Client ID**, which is a different kind of credential
from a Maps or Generative AI API key:

1. Go to https://console.cloud.google.com/apis/credentials
2. Create Credentials → OAuth client ID → Application type: **Web application**
3. Under "Authorized JavaScript origins" add your frontend's dev URL, e.g.
   `http://localhost:5173`
4. Copy the Client ID into **both**:
   - this backend's `.env` as `GOOGLE_CLIENT_ID`
   - the frontend's `.env` as `VITE_GOOGLE_CLIENT_ID`
   (they must be the exact same value)

## 5. API reference

| Area | Endpoints |
|---|---|
| Auth | `POST /api/auth/google` `{credential}`, `PATCH /api/auth/role` `{role}`, `GET /api/auth/me` |
| Zones | `GET/POST /api/zones`, `PATCH/DELETE /api/zones/:id` (admin for writes) |
| Incidents | `POST /api/incidents` (multipart: zone, citizenNote, image), `GET /api/incidents`, `GET /api/incidents/open`, `GET /api/incidents/:id`, `POST /api/incidents/:id/respond`, `PATCH /api/incidents/:id/status` |
| Predictions | `GET /api/predictions` — real week-over-week trend per zone |
| Teams | `GET /api/teams` (admin) |
| Dashboard | `GET /api/dashboard/stats`, `/charts`, `/insights`, `/my-stats` |
| AI Assistant | `POST /api/assistant/ask` `{question}` |
| Scanner | `POST /api/scanner/analyze` (multipart image), `GET /api/scanner/history`, `GET /api/scanner/categories` |

All endpoints except `POST /api/auth/google` and `GET /api/zones`/`GET /api/scanner/categories` require `Authorization: Bearer <token>`.
